# Сопровождение StatusDesk Console

Исходный проект — CortenDesk. Наша версия живёт в ветке `codex/statusdesk-main` форка `Liaders/cortendesk`; ветка `main` остаётся справочной версией оригинала. Локально `origin` указывает на наш форк, `upstream` — на оригинал.

## Обычная доработка

Создать отдельную ветку от `origin/codex/statusdesk-main`, внести небольшое изменение, обновить переводы и тесты, открыть PR в наш форк. После проверки и принятия CI соберёт свой Docker-образ. Комментарии в коде и описания PR пишем на английском. Новые надписи переводим на все языки, объявленные в `User::LOCALES`.

## Получение нововведений автора

В GitHub открыть Actions → Review upstream changes → Run workflow. По умолчанию выбирать `main`. `beta` выбирать только для осознанного перехода на бету с отдельной проверкой миграций.

Если новых изменений нет, процесс завершится без PR. Если изменения объединяются, появится отдельная проверочная ветка, запустятся тесты и проверка контейнера. В отчёте будет ссылка для открытия PR вручную. При конфликте процесс остановится и перечислит файлы — рабочая ветка не изменится. Автоматического принятия PR и обновления сервера нет.

Если автор включил нашу функцию в оригинал, сравнить реализацию, по возможности перейти на авторскую и сохранить тесты нужного нам поведения. Так уменьшается объём собственных изменений и упрощаются следующие обновления.

## Сборка и выпуск

После успешных тестов и проверки контейнера образ публикуется в `ghcr.io/liaders/statusdesk-console`. В отчёте Actions сохраняется точная ссылка с `@sha256:…`. Для установки использовать именно её. `edge` — указатель на последнюю сборку, а не разрешение обновлять рабочий сервер.

Номер нашей версии находится в `STATUSDESK_VERSION`, версия основы — в `VERSION`, точный исходный коммит — в `statusdesk-upstream.json`. При выпуске менять номер нашей версии отдельным проверяемым коммитом. Ссылки и авторство CortenDesk сохраняются.

## Рабочий сервер

Настройка форка сама по себе не меняет установленный сервер. Переход с временного образа с отчётом на образ StatusDesk Console — отдельная операция после теста на свежей копии базы и разрешения пользователя.

Перед переключением сохранить реальные параметры контейнера, данные, ключи и сессии. Не подставлять существующий рабочий том в пример Compose без проверки всех путей и параметров. Старый контейнер сохранять остановленным с отключённым автозапуском. После миграций базы нельзя считать замену образа достаточным откатом: сначала нужно проверить совместимость схемы.

Секреты, копии рабочей базы и ключи не коммитить и не загружать в GitHub Actions. В тестах использовать только изолированную SQLite в памяти и синтетические данные.
